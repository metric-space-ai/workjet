# Computer assignment integration

The desktop Computer settings page sends bounded list/assign/unassign requests through typed preload IPC to the exact selected CTOX guest. The guest invokes the existing `workjetComputerControl` function. CTOX's `ctox.workjet.computer.*` commands and `workjet_computers` WebRTC projections own the persisted assignment; no membership HTTP route or local grant is enabled by this integration.

The renderer retains only the native-confirmed projection in memory and correlates responses to the selected presentation instance and generation. Desktop Main additionally checks guest identity, response action, computer ID, assignment status, schema and response byte size. A pending command never holds the guest pool lock. The scope mapper joins the confirmed opaque computer ID with the saved Workjet computer's environment; connection type or editable presentation alone does not establish remote membership.

The native contract is defined in CTOX `src/core/business_os/store_workjet_computers.rs` and the browser adapter in `src/apps/business-os/app.js`. It is present on CTOX main at `67e44b11d2b19cbc1bfa60baddae4cc23de5dba3`. The existing Workjet HTTP membership scaffolding remains unmounted and unused. This change does not provide its missing physical-host authority adapter, nor infer backend host identity from an SSH hostname. The UI submits normal workstation assignments, without enabling self-hosted backend co-location. That separate workflow needs explicit native authority and confirmation integration.

Real UI acceptance must establish assignment and removal against the selected instance, exclusion after switching instances, retention after reload, and remote coding on the assigned machine. Unit tests and a visible Connected row are insufficient. Mobile hosts still require their own bridge adapter before this desktop workflow can be accepted there; unsupported hosts return an explicit update message. No mobile assignment acceptance is claimed.

Computer-control failures distinguish a rejected guest command, an unavailable sync connection, a native query that is not supported, and an invalid response contract. Only fixed codes cross the guest boundary; raw exceptions are not returned because they can contain credentials. These diagnostics do not authorize fallback writes, synthesize membership, or turn a failed query into an empty successful inventory.
