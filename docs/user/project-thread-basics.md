# Project thread basics

Changing a chat's harness checks its model against the target harness's reported models and the gateway catalog. If the model is unavailable, the composer selects the target harness's checked default and explains the change below the composer. A harness without a checked default cannot be selected until its model list is refreshed in Settings.

A chat commissioned by a project Supervisor or a Persistent Worker becomes a One-Shot even when the request does not select a role. It receives its own worktree before its first turn and uses the existing single-PR submission and archival lifecycle. Chats opened manually remain ordinary chats. One-Shots remain leaves and cannot commission children.

Newly imported project histories inherit the active project Supervisor's permission mode and execution policy. When no Supervisor policy is available, they use the project's normal default. The thread header's approval policy selector can restore the current project policy or set a permission override. Permission changes are saved for that thread and disabled during active work. A retained autonomous-worktree policy still requires a harness that can enforce it; selecting Full access does not remove that policy.

If the desktop cannot read its saved connections, worker access can still use the local service with the matching environment identity. Workjet shows one informational notice and preserves the saved catalog. A local-service authorization failure is still reported normally.
